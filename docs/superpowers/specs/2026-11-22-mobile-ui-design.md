# ZPlayer Music 移动端 UI 设计

- 日期：2026-11-22
- 状态：设计已确认，待书面审阅
- 目标平台：Android、iOS 18 及以上；iOS 26 重点验证玻璃视觉
- 技术基础：Rust、Slint 1.18.1、现有 ZPlayer Music 业务核心

## 1. 目标与范围

为 Android 和 iOS 建立共享业务核心、独立移动 UI 壳的音乐播放界面，完成真实数据驱动的核心听歌闭环：

1. 首页浏览推荐内容。
2. 搜索单曲、专辑和歌单。
3. 查看歌单或专辑详情。
4. 播放歌曲、查看队列和歌词。
5. 播放/暂停、上一首、下一首、播放模式和进度拖动。
6. 修改并持久化移动端适用设置。

手机竖屏、手机横屏和平板共用页面状态和业务逻辑，但采用各自适合的导航与内容布局。

### 不在首期范围内

- MV、电台和桌面歌词。
- 锁屏控制、媒体通知、后台播放保活、音频焦点与中断恢复。
- 桌面标题栏、托盘、窗口快捷键、输出设备切换等桌面专属能力。
- 为移动端新增推荐服务或改变现有业务配置的含义。
- 直接调用或宣称使用 Apple 原生 Liquid Glass API。

## 2. 已确认的关键决策

- 一级导航采用三个入口：首页、搜索、设置。
- 手机竖屏使用底部导航，迷你播放条常驻在其上方。
- 手机横屏保持移动端内容风格，但改用左侧窄导航栏。
- 平板采用类似 PC 的左侧栏、内容区和底部播放栏结构，但保留移动端触控尺寸、圆角、间距和平台材质。
- iOS 26 使用“封面沉浸玻璃”：封面取色背景、模糊、半透明表面、高光和细边框。
- Android 使用克制的 Material 风格，不复制 iOS 玻璃效果。
- 代码组织采用“共享 Rust 核心与数据契约 + 独立移动端 UI 壳”，不改用单一响应式桌面窗口，也不复制一套业务控制层。

## 3. 总体架构

### 3.1 UI 与构建边界

- 桌面、Web 和移动端分别选择各自的 UI 编译入口。
- 移动端入口为独立 AppWindow，拥有移动页面、组件和视觉 token；现有 `ui/appwindow.slint` 不增加移动布局分支。
- 构建脚本根据移动特性和目标操作系统选择移动 UI。桌面与 Web 继续使用现有入口。
- Android 与 iOS 共用布局、页面状态和交互逻辑，通过平台材质和必要的能力适配区分表现。

UI 结构：

```text
ui/mobile/
├── appwindow.slint
├── pages/
├── components/
└── theme.slint
```

现有共享歌曲、歌单、专辑等数据模型以及语言资源继续复用。移动主题独立维护，避免修改桌面 Theme 后引起桌面视觉回归。

### 3.2 Rust 与原生宿主边界

- Rust 继续负责搜索、详情、播放、队列、歌词、设置和持久化。
- 移动端绑定层负责把 Slint 回调转换为既有业务动作，并把业务结果转换为 UI 属性。
- Slint 页面不直接执行网络请求、访问播放器或读写配置文件。
- 桌面专属逻辑通过条件编译隔离，不进入移动构建。
- 原生宿主只负责应用窗口、平台生命周期、安全区注入和平台打包，不维护第二套页面或播放状态。
- Android `applicationId` 与 iOS `bundleIdentifier` 统一为 `com.music.zplayer`；与桌面端 `com.zplayer.music` 不同，必须在原生宿主工程中单独配置，并同步 Android 源码 package 声明与目录结构。
- 所有异步 UI 更新统一切回 Slint UI 线程。

### 3.3 安全区与尺寸单位

- 原生宿主注入顶部、底部以及当前平台需要的左右安全区。
- Slint 根据安全区和当前布局计算导航、迷你播放条、播放层及弹层的位置。
- 文档中的 dp 指平台逻辑尺寸，实现时映射为 Slint 逻辑像素。
- 可点击控件的触控目标至少为 48dp，视觉图标可以小于触控区域。

## 4. 自适应布局

布局依据可用逻辑尺寸判断，不依赖设备型号。最短边小于 600dp 为手机，最短边达到 600dp 为平板；手机中宽大于高时视为横屏。

| 形态 | 判断条件 | 导航 | 播放控制 | 内容布局 |
| --- | --- | --- | --- | --- |
| 手机竖屏 | 最短边 < 600dp，高 >= 宽 | 三栏底部导航 | 导航上方常驻迷你播放条 | 单列移动列表与页面 |
| 手机横屏 | 最短边 < 600dp，宽 > 高 | 左侧 64–72dp 窄导航栏 | 内容区底部迷你播放条 | 保持移动列表风格，利用横向空间 |
| 平板 | 最短边 >= 600dp | 带图标和文字的完整左侧栏 | 独立底部播放栏，展示完整进度和控制 | 宽列表；内容宽度足够时使用双栏 |

- 平板只在信息结构上借鉴 PC，不使用桌面窗口控件或密集鼠标交互。
- 平板内容可用宽度达到 840dp 时采用双栏，否则使用宽单列。
- 三种导航只是同一导航状态的三种呈现，不分别创建页面实例。
- 旋转屏幕或改变窗口尺寸只重组布局，不重新加载页面、不重新搜索、不重置滚动位置、不影响播放。

## 5. 页面与组件

### 5.1 页面层级

一级页面：

- **首页**：复用现有推荐歌单、热门歌曲等内容与数据入口。
- **搜索**：支持单曲、专辑、歌单；保留搜索关键词、类型和当前会话结果。
- **设置**：提供深浅色与主题色、语言、音质、音源、缓存上限及缓存清理。

二级页面：

- **歌单/专辑详情**：展示资源信息、歌曲列表、加载与错误状态。
- 从详情返回后恢复原一级页面的数据和滚动位置。

播放层：

- 展示封面、歌曲信息、播放进度、播放模式、上一首、播放/暂停、下一首、歌词和队列。
- 手机竖屏使用全屏播放层，队列以移动弹层呈现。
- 手机横屏和平板使用左右分区：左侧封面与控制，右侧歌词或队列；默认显示歌词，队列按需展开。
- 手机的一级和二级页面显示迷你播放条，平板显示独立底部播放栏；播放层打开时隐藏对应常驻播放控制，关闭后恢复。

### 5.2 共享移动组件

- 底部导航、窄导航栏、平板侧栏。
- 迷你播放条和平板底部播放栏。
- 歌曲列表项、封面、详情头部、进度条和播放控制按钮。
- 歌词视图、队列视图和移动弹层。
- 设置分组及设置项。
- 加载、空结果、错误和重试视图。
- iOS 玻璃表面与封面环境背景；Android Material 表面。

列表滑动与点击必须可同时使用，进度拖动不能触发页面滚动或误切歌。

## 6. 平台视觉

### 6.1 iOS 封面沉浸玻璃

- 当前封面决定背景主色，背景使用取色渐变、模糊和半透明叠层。
- 底部导航、窄侧栏、平板侧栏、迷你播放条、播放层关键表面及弹层使用统一玻璃 token。
- 文本和图标必须在深浅封面下保持可读，必要时通过表面遮罩调整对比度。
- 封面取色和模糊结果按歌曲缓存，只在歌曲变化时更新，不随播放进度逐帧计算。
- iOS 26 真机验证完整效果；较低 iOS 版本或模糊性能不足时使用封面色渐变和半透明静态材质。
- 玻璃效果是 Slint 自绘视觉，不依赖 Apple 原生 Liquid Glass API。

### 6.2 Android Material

- 使用与 iOS 相同的布局和交互，但采用 Material 导航、表面、状态和弹层样式。
- 不使用高成本全屏实时模糊；以主题色、封面色的克制渐变和表面层级建立反馈。

### 6.3 通用降级

封面下载、解码或取色失败时使用本地默认封面和主题色背景。视觉降级不改变页面结构、数据状态或交互。

## 7. 数据流与状态

### 7.1 单一状态源

- Rust 是搜索、详情、播放、队列、歌词和设置的唯一状态源。
- UI 通过回调表达用户动作，通过属性接收业务结果，不在组件内复制播放状态。
- 迷你播放条、播放层、歌词和队列观察同一当前歌曲与播放状态。

### 7.2 页面数据

- 首页和详情首次进入时加载，搜索在提交时发起请求。
- 切换一级标签、旋转屏幕或改变平板尺寸不重新请求。
- 搜索和详情请求使用递增序号，仅允许最后一次请求更新对应页面。
- 新搜索保留关键词和搜索类型；加载期间使用明确加载状态，不用空白页面造成闪烁。
- 点击列表歌曲时，以当前列表作为队列上下文并播放所点歌曲；队列面板支持查看和选择歌曲。

### 7.3 播放与进度

- 播放、切歌和播放模式动作由现有 Rust 播放逻辑处理。
- 进度拖动期间仅更新本地预览，松手后执行一次 seek。
- seek 后及正常播放期间以 Rust 同步的真实进度为准，避免 UI 预估进度与播放器互相覆盖。
- 播放失败时恢复真实状态并提示原因，UI 不自行切换下一首。

### 7.4 设置与持久化

- 移动端复用现有配置结构和持久化逻辑。
- 设置修改立即生效，并按现有规则保存。
- 当前标签、详情导航、搜索内容、滚动位置和播放层状态属于会话状态，旋转时保留，不新增跨启动恢复规则。
- 队列、当前歌曲和进度的跨启动恢复继续遵循现有核心行为。

## 8. 错误处理

- 首次加载失败：显示页面级错误说明和重试按钮。
- 已有内容的页面操作失败：保留现有内容，使用轻量提示说明失败。
- 搜索失败：保留关键词、类型、历史和已有结果；发起新请求时清除旧错误。
- 无搜索结果：显示独立空态，不当作网络错误。
- 播放失败：显示原因并保持 UI 与真实播放状态一致。
- 设置保存失败：提示用户并恢复到最后一个有效值。
- 封面失败：使用默认封面和主题色，不阻塞歌曲播放。
- 歌词不可用：显示歌词空态，不影响其他播放控制。
- 网络、存储和播放错误接入现有日志体系，不在界面暴露敏感配置或内部堆栈。

## 9. 构建与测试设计

### 9.1 自动化验证

- 将布局形态判断实现为纯逻辑，测试手机竖屏、手机横屏、平板及安全区变化。
- 测试请求序号，验证旧搜索和详情响应不能覆盖新状态。
- 运行现有 Rust 测试，并检查移动端、桌面端和 Web 端编译。
- 对桌面首页、搜索、详情、播放和设置执行基础回归，确认共享改动没有改变桌面布局和行为。

### 9.2 设备矩阵

- Android arm64-v8a 手机真机。
- iOS 手机真机，其中 iOS 26 设备用于玻璃视觉验收。
- Android 平板和 iPad，用于平板导航、双栏内容和播放层验证；模拟器可辅助布局检查，但不能替代双平台手机真机验收。
- 刘海屏/灵动岛和带手势条设备，用于顶部、底部及横屏安全区验证。

iOS 构建和真机验证必须在具备 Xcode 的 macOS 环境执行。未实际构建或运行的平台不得标记为验证通过。

### 9.3 核心验收标准

1. 首页真实数据加载成功，可进入歌单或专辑详情并播放歌曲。
2. 搜索单曲、专辑和歌单均可用，进入详情和返回正常，快速操作不会出现旧响应覆盖。
3. 播放/暂停、上一首、下一首、播放模式、进度拖动、队列查看与选曲均可用，各播放视图状态一致。
4. 播放中旋转屏幕或改变平板尺寸，不中断播放、不丢失页面、搜索或滚动状态。
5. 设置修改立即生效，重启后按现有规则恢复。
6. 网络失败、无结果、封面失败、歌词不可用和播放失败均有明确反馈，不会卡死或显示虚假状态。
7. 手机横屏显示窄侧栏，平板显示完整侧栏；导航、进度和按钮不被系统区域遮挡。
8. iOS 26 的封面取色和玻璃材质符合设计，性能不足时可自动降级且交互不变。
9. Android 保持 Material 视觉，不出现 iOS 专属玻璃样式。
10. 现有桌面和 Web 行为保持正常。

## 10. 实施约束

- 保持桌面 UI 与业务行为不变，共享代码只进行移动端所需的最小抽取。
- 优先复用现有服务与模型，不在移动绑定层复制业务规则。
- 平台效果必须先验证 Slint 在目标设备上的实际渲染与性能，再决定启用动态模糊或静态降级。
- 工作区已有改动不属于本设计，不得回滚、覆盖或混入设计文档及后续实现提交。

## 11. GitHub Actions CI

移动端 CI 独立于现有桌面/Web 发布工作流，避免移动端未就绪阻塞桌面发布。

### 11.1 PR 编译检查

- Android：配置 JDK、Android SDK/NDK 与 `aarch64-linux-android`，检查 Rust、Slint 与 Gradle 宿主，并构建 Debug APK。
- iOS：在 macOS Runner 上检查 Rust 与 Xcode 宿主，执行无签名 Simulator 构建。
- 运行共享 Rust 单元测试及移动布局判断测试。
- 任一平台失败只阻塞移动端 CI，不影响现有 Release 工作流。

### 11.2 手动出包

- Android 始终上传可供测试安装的 Debug APK；配置发布 Keystore Secrets 后，额外构建并上传签名 Release APK。
- iOS 配置证书、描述文件和 Team ID Secrets 后，构建并上传签名 IPA。
- 未配置 iOS 签名时，只上传 Simulator `.app` 包用于验证，不将无签名包冒充成真机可安装 IPA。
- 证书、Keystore、密码和描述文件全部通过 GitHub Secrets 注入，不写入仓库或日志。

### 11.3 实施顺序

先建立最小 Android/iOS 宿主与移动 UI 壳，确保真实构建链路存在，再接入 CI；随后随核心页面开发持续运行。不创建当前必然失败的空工作流。
