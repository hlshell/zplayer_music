# ZPlayer Music 移动端 UI 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 ZPlayer Music 建立可在 Android（arm64-v8a）与 iOS 18+ 真机运行的移动端 UI，覆盖首页/搜索/设置、歌单与专辑详情、播放层与队列、设置持久化，并适配手机竖屏、手机横屏窄侧栏和平板类 PC 布局，iOS 26 呈现封面沉浸玻璃。

**Architecture:** 共享现有 Rust 业务核心（搜索/详情/播放/队列/设置）与 Slint 数据模型；新增独立 `ui/mobile/` UI 壳与原生宿主工程。`build.rs` 按 `mobile` feature 选择 `appwindow-mobile.slint`；`main.rs` 按 feature 分流桌面/移动入口；`audio` 与 `storage` 门面新增 mobile 实现。原生宿主只负责窗口、生命周期、安全区与打包。移动端 CI 独立于现有桌面 Release 工作流。

**Tech Stack:** Rust + Slint 1.18.1（`unstable-winit-030`）、rodio/cpal（非 wasm 共享）、Android Gradle（AGP + NDK）、Xcode（iOS）、GitHub Actions。

**Spec:** `docs/superpowers/specs/2026-11-22-mobile-ui-design.md`

**Bundle/Application ID:** `com.music.zplayer`（Android `applicationId` 与 iOS `bundleIdentifier` 统一；与桌面 `com.zplayer.music` 不同）。

```rust
//! 纯逻辑：根据可用逻辑尺寸判定移动端布局形态，便于单元测试。
//! 规则见 spec §4：最短边 < 600dp 为手机（宽>高为横屏，否则竖屏）；
//! 最短边 >= 600dp 为平板。内容可用宽 >= 840dp 时平板启用双栏。

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum LayoutKind {
    PhonePortrait,
    PhoneLandscape,
    Tablet,
}

pub fn classify(width: f32, height: f32) -> LayoutKind {
    let shortest = width.min(height);
    if shortest >= 600.0 {
        LayoutKind::Tablet
    } else if width > height {
        LayoutKind::PhoneLandscape
    } else {
        LayoutKind::PhonePortrait
    }
}

/// 平板内容区是否采用双栏（spec §4：内容可用宽度 >= 840dp）。
pub fn should_use_two_column(content_width: f32) -> bool {
    content_width >= 840.0
}
```
